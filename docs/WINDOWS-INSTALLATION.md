# Windows build, portable installation and recovery

Integration build from0.1.0-alpha.2,2026-09-13. Existing studio and profile schema v2 remain. This is an unsigned portable Windows x64 package, not an MSI, signed installer, auto-updater or public release. Tested on Windows10.0.26200 (Windows11 build26200); another clean machine has not been tested.

## Clean-machine procedure (repeatable instructions; second-machine execution pending)

1. Copy the source/demo kit to a user-writable directory, preferably outside a live sync folder. Install Node24.16.0 x64/npm11.13.0 and Git for the optional firmware SDK. Verify `node --version` and `npm --version`. Keep package-lock.json unchanged. Network access to npm and Electron downloads is needed on first install. No API account or secret is needed.
2. In PowerShell at the project root: `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `npm run test:desktop`, `npm run package:win`. npm ci runs dependency lifecycle scripts including Electron's download; use the reviewed lockfile. Do not use npm update for reproduction. If node-hid cannot use its bundled Windows binary, stop and capture the error; a source rebuild requires the appropriate Visual Studio C++ Build Tools/Python and Electron ABI configuration, which this procedure has not verified on a clean PC.
3. Output: `release/0.1.0-alpha.2-integration/SignalKey-win32-x64/SignalKey.exe`. Keep the entire adjacent directory, including resources/app and native dependencies. Copying only the EXE does not install the application. Run from a local user-writable folder. No service, driver installer, registry uninstall entry or administrator installation is supplied.
4. To replay packaged upgrade/crash evidence, also retain the original `release/0.1.0-alpha.2/SignalKey-win32-x64` baseline and run `npx tsx scripts/integration-demo.ts`. This launches isolated copies using temporary user data and a test-only native-approval adapter. It does not click or validate the real Windows approval dialog. For a manual demonstration, create a trusted workflow, enable it through the real confirmation dialog, assign press/run and double/cancel, run it and inspect Output/Run history; quit via tray before reopening.
5. For CAD, use OpenSCAD2021.01 and Python with trimesh4.8.1/numpy2.3.3. `scripts/verify-assemblies.py` expects the documented `.local` paths. For firmware use `scripts/setup-firmware-tools.ps1` and `scripts/build-firmware-check.ps1` with firmware/toolchain-lock.json. Link-check outputs deliberately have invalid USB IDs and are not flashable deployment artifacts. Rebuild of an authorized-ID UF2 and actual hardware remain blocked.

## Data location and upgrade

Default Windows user data is `%APPDATA%\SignalKey` (Electron userData). Test scripts pass `--user-data-dir` and never use the normal profile directory. The actual path is recorded in integration-demo.json for that isolated test. Contents: profiles.json (profiles, selection, target), history.json (last100 run metadata), active-run.json (in-flight intent), sdk.json (ephemeral local port/token), Electron preferences/cache/logging files and preserved corrupt-profile copies. Output text is a bounded in-memory tail, not full durable command logs. Treat sdk.json as a credential; do not include it in a shared demo kit.

Quit through the tray first; closing the window can leave the app running. Back up the whole userData directory while stopped. Install an upgrade into a new directory; retain the old folder until validation. Start the new EXE under the same account/userData and check profile names, arguments, working directories, selection, bindings and enabled flags before pressing. No workflow is automatically executed at startup. Custom absolute command paths are preserved, not automatically relocated. Default sample paths and custom paths that refer to an old install directory require review before deleting that directory.

The integration test created a custom enabled profile in the original alpha.2 binary, ran it, fully quit, launched the integration binary and confirmed byte-identical profiles.json and retained history. It also relaunched a full package copy from another installation path. This verifies same-machine portable upgrade/relocation; it does not establish clean-machine, MSI or all historical-version compatibility. The Electron EXE hash alone cannot identify app code: use the demo kit's full per-file SHA256 manifest.

## Interrupted command policy

A flushed intent file is atomically replaced before spawn. The service reserves a single execution slot before that disk operation, so simultaneous requests cannot both launch. Final history is written before clearing intent. If the companion disappears first, startup records the unresolved intent as interrupted/unknown and never replays it. Arbitrary commands may already have changed files or remote systems and a child can outlive a crash. Cancel/timeout is also not rollback. There is no automatic retry and no exactly-once promise for arbitrary side effects. Retry manually only after checking the external result or using a command with its own durable idempotency key.

If active-run.json is unreadable, execution fails closed with RECOVERY_REQUIRED. Quit; copy the entire data directory and inspect the original command's external effects. Preserve the malformed record for investigation. Only after reconciliation, move the original active-run.json into a dated recovery folder within your backup and restart; record your disposition. Do not delete it while a command may be running. Files are flushed before rename, but abrupt power/storage failure and directory-entry durability have not been validated.

New history state `interrupted` is not understood by the old alpha.2 history parser. Back up before downgrading; restore the matching old history backup if needed. Profile schema remainsv2. Never replace current profiles with defaults to solve a history issue.

## Uninstall and recovery

Disable Launch at login in SignalKey if enabled, then quit the tray app. Remove only the verified installation directory and any shortcut you created. Portable uninstall intentionally leaves `%APPDATA%\SignalKey` for recovery. Delete user data only as a separate explicit user decision after backup. Reinstalling the folder and launching with the same data path restores profiles. Actual folder deletion is documented, not exercised on the user's install; relocation/reinstall was tested in isolated temp storage. No file associations or system driver removal are required by this package.

Unsigned packages may trigger Windows reputation prompts. Do not disable system protection. A signed distribution requires a controlled certificate/signing pipeline, trusted timestamp, signature verification and a separate release review; none is claimed here. Packaging repeats from pinned dependencies, but byte-for-byte reproducibility is not demonstrated: generated timestamps and packaging metadata may differ. Full manifests establish the exact tested bytes.
