# Architecture and decisions

Electron main owns the runner, profile persistence, HID, local API and OS integration. The sandboxed React renderer reads snapshots and invokes a fixed set of validated operations through the preload bridge. It has no Node or general filesystem/shell API. Executable changes and enabling a command require a native main-process review dialog; imported files are disabled and assigned fresh IDs.

`Service` connects observed process state to `Transport`; both virtual and HID implementations share the binary codec. A physical identity is selected by unique serial and never substituted by discovery order. Reconnect retries every two seconds for that selected identity. Commands are not replayed. Sleep closes transport and cancels an active process; resume reopens the selected identity. These OS event handlers exist, but physical sleep/wake tests remain pending.

Runner policy: one job, overlapping requests rejected, explicit executable plus argument array and absolute cwd, `shell:false`, 100 ms–1 hour timeout, latest 32 KiB output, exit code determines success. Cancellation uses Windows `taskkill /PID /T /F` or a POSIX process group. This is best-effort tree cleanup, not a Windows Job Object containment boundary; an escaping/reparented process is not guaranteed to be contained. Run only trusted commands. Failure to clean up is logged. A future Job Object adapter should strengthen lifecycle guarantees before untrusted/general automation use.

Profiles v2 are strictly validated and atomically saved through serialized mutations. Migrations preserve old sample bindings; imports are disabled and cross-profile run references are reset to self. Create/duplicate are disabled by default. Each press/double/hold binding can run self/another reviewed workflow, cancel, or do nothing. Deletion refuses the last profile and profiles referenced by another binding. Damaged configuration is copied aside before defaults are restored. History persists the latest100 run metadata records without restoring a live success on restart. Custom light colors/patterns remain deferred.

HID handshake queries capabilities and validates required feature bits and numeric ranges, then reads state. Light updates are sent on change and read back; heartbeat is every two seconds. Simulator fault controls pause heartbeat or disconnect without action replay. Device reported light is not optical evidence.

The local SDK uses authenticated loopback HTTP because Node's portable named-pipe server API does not directly configure a per-user Windows ACL. It listens only on 127.0.0.1, allocates an ephemeral port, creates a random session token, rejects all Origin-bearing requests, bounds bodies to 8 KiB, rate-limits to 30 requests/second and limits connections. Connection metadata lives in the app user-data directory with mode 0600 on platforms that honor it. Windows relies on inherited user-profile ACLs: this is **not proof of a custom per-user pipe ACL**, and same-user processes can read the token. Actions must already be enabled through the desktop app. `/run` returns acceptance, never success; clients inspect `/status`. `/events` provides press events only. SDK status expires after six seconds unless refreshed.

State priority and wire layout are in `packages/protocol/README.md`. Renderer reads snapshots at 300 ms; service synchronization checks every250 ms, sends changed light/brightness plus readback, and sends heartbeat every two seconds. The firmware gesture disambiguation window adds 300 ms to single-press dispatch. The aspirational <100 ms target has not been demonstrated and is not a release claim.

ADR 001: use brief's Electron/React/Vite stack for native HID and Windows packaging. ADR 002: one cohesive service, shared protocol/SDK source folders, no unnecessary package workspace fragmentation. ADR 003: software-first simulator remains functional without hardware. ADR 004: no cloud/account/telemetry. ADR 005: hardware artifacts remain review inputs until native CAD and physical evidence exist.
